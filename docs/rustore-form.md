# Ответы для формы RuStore

Готовые тексты для раздела «Безопасность данных» в RuStore Консоли. Можно
копировать целиком.

Актуально для версии `0.3.0` (`versionCode 3`), пакет `ru.petproject.giribro`.

## 1. Запрашиваемые данные

**Типы данных, которые собирает приложение: не выбираем ни одного.**

Приложение не собирает, не передаёт и не хранит персональные данные на серверах.
У приложения нет доступа в интернет: в APK отсутствует разрешение `INTERNET`.

Всё, что пользователь вводит, остаётся в локальной базе на его устройстве:

- тренировки (дата, упражнение, подходы, вес, повторения, заметки);
- замеры тела (вес, обхваты, дата);
- профиль спортсмена (пол, возрастная группа, вес для нормативов);
- настройки приложения (тема, цели, параметры таймера);
- фото-карточка тренировки — PNG формируется на устройстве и сохраняется только
  по выбору пользователя через системный диалог или системное меню «Поделиться»;
- резервная копия — JSON-файл создаётся на устройстве по действию пользователя
  или по включённому им автобэкапу и сохраняется в выбранную папку;
- кадры камеры — только при включённом счётчике повторов, обрабатываются
  на устройстве встроенной моделью и не сохраняются и не передаются.

Нет аккаунтов и авторизации, нет аналитики, рекламы, crash-репортинга и
облачной синхронизации. Данные не покидают устройство и удаляются вместе с
приложением.

Если форма требует хотя бы один пункт, выбирайте «Приложение не собирает
данные» / «Нет». Не отмечайте «Данные о здоровье»: приложение только хранит
введённые пользователем записи локально и не передаёт их разработчику.

## 2. Чувствительные разрешения

В APK фактически объявлены семь пользовательских разрешений:

| Разрешение | Тип | Зачем |
| --- | --- | --- |
| `CAMERA` | камера | счётчик повторов для толчка, длинного цикла и рывка: фронтальная камера on-device распознаёт скелет. Видео не записывается и не передаётся; разрешение необязательно, без него остальные функции работают |
| `POST_NOTIFICATIONS` | уведомления (Android 13+) | постоянное уведомление интервального таймера с текущей фазой и кнопками «Пауза/Продолжить», «Стоп»; напоминание о резервной копии |
| `FOREGROUND_SERVICE` | foreground-сервис | таймер тренировки продолжает считать время, когда приложение свёрнуто или экран заблокирован |
| `FOREGROUND_SERVICE_SPECIAL_USE` | foreground-сервис (special use) | тип сервиса для интервального таймера: подтип `Interval work/rest timer for kettlebell training` |
| `VIBRATE` | вибрация | короткая вибрация при смене фаз таймера и по завершении тренировки |
| `WAKE_LOCK` | обычное разрешение | WorkManager удерживает процессор активным, пока выполняется фоновая задача автобэкапа |
| `RECEIVE_BOOT_COMPLETED` | обычное разрешение | после перезагрузки телефона WorkManager восстанавливает расписание еженедельного автобэкапа |

Разрешение `POST_NOTIFICATIONS` запрашивается только в момент первого запуска
таймера или включения автобэкапа. Разрешение `CAMERA` запрашивается только
при открытии счётчика повторов. Если пользователь откажет, приложение
продолжает работать: таймер виден на экране, автобэкап выполняется, но
уведомления и напоминания не показываются, а счётчик камеры недоступен —
ручной ввод повторов остаётся.

В APK также есть служебное разрешение
`ru.petproject.giribro.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`, которое
автоматически добавляет AndroidX для защиты внутренних broadcast-приёмников. Оно
имеет уровень `signature` и не запрашивается у пользователя.

Приложение **не запрашивает**: микрофон, геолокацию, контакты, SMS,
телефон, календарь, доступ ко всей галерее и внешнему хранилищу, `INTERNET`,
`ACCESS_NETWORK_STATE`, `READ/WRITE_EXTERNAL_STORAGE`, `QUERY_ALL_PACKAGES`.
Для автобэкапа используется SAF: пользователь сам выбирает папку системным
диалогом, и приложение получает доступ только к ней.

### Пояснение для модератора (копировать в поле)

> «ГириБро» — офлайн-дневник тренировок с гирями и интервальный таймер.
> Приложение не собирает и не передаёт данные, не имеет доступа в интернет.
> `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_SPECIAL_USE`
> нужны для работы интервального таймера: пользователь запускает тренировку, и
> отсчёт продолжается при свёрнутом приложении, а в шторке уведомлений
> отображаются текущая фаза (работа/отдых), оставшееся время и кнопки
> «Пауза/Продолжить» и «Стоп». `VIBRATE` используется для короткого сигнала при
> смене фаз и завершении тренировки. `POST_NOTIFICATIONS` также показывает
> напоминание, если автобэкап не создавался дольше 30 дней. `WAKE_LOCK` и
> `RECEIVE_BOOT_COMPLETED` нужны WorkManager для фоновой еженедельной резервной
> копии: чтобы задача завершилась при заблокированном экране и восстановилась
> после перезагрузки. Копия сохраняется только в папку, которую пользователь
> выбрал через системный диалог SAF. Разрешение на уведомления запрашивается в
> момент запуска таймера или включения автобэкапа; без него таймер и автобэкап
> работают, но без уведомлений. `CAMERA` нужна только для необязательного
> счётчика повторов: пользователь сам открывает экран счётчика, фронтальная
> камера на устройстве распознаёт скелет для толчка, длинного цикла и рывка.
> Модель распознавания входит в APK, видео не записывается, кадры не
> сохраняются и не отправляются, интернет не используется. Без разрешения на
> камеру остальные функции работают, а повторы можно вводить вручную. Других
> разрешений, включая микрофон, геолокацию, контакты и доступ ко всей файловой
> системе, приложение не запрашивает.
> Фото-карточка тренировки рисуется локально и передаётся в системное меню
> «Поделиться» только по действию пользователя, без доступа к чужой галерее.

## 3. Интеграции

**Интеграций нет.** Ничего не выбираем и не добавляем.

Приложение не использует:

- рекламные сети и SDK (Ads, mediation);
- аналитику и продуктовую аналитику (Firebase Analytics, AppMetrica и др.);
- crash-репортеры и APM;
- push-уведомления (FCM, RuStore Push) — уведомление таймера локальное;
- авторизацию через соцсети, Google, VK ID, RuStore ID;
- платежи и подписки (RuStore Pay, Google Play Billing);
- карты, геолокацию, соцсети, мессенджеры;
- облачную синхронизацию и backend.

В зависимостях AndroidX (Compose, Navigation, Lifecycle, Room, WorkManager,
Core), CameraX для доступа к камере и MediaPipe Tasks Vision — встроенный
on-device движок распознавания позы. MediaPipe работает локально, без сети и
без обращения к серверам Google; модель `pose_landmarker_lite.task` лежит
в APK. Это не интеграция с внешним сервисом.

Внутри MediaPipe Tasks есть встроенный компонент статистики (Google
DataTransport / CCT), который библиотека создаёт при инициализации задачи.
Отключить его через API библиотеки нельзя, но отправить данные он не может:
в APK нет разрешения `android.permission.INTERNET`, поэтому любые попытки
сетевого обмена блокируются системой на устройстве. Разрешения
`INTERNET` и `ACCESS_NETWORK_STATE` явно удалены из манифеста
(`tools:node="remove"`), приложение работает полностью офлайн.

Системное «Поделиться» (`Intent.ACTION_SEND`) и `FileProvider` — это штатные
механизмы Android, а не интеграция с конкретным сервисом.

Если RuStore автоматически нашёл в файле интеграции — в этом APK их быть не
должно; список должен быть пустым.

## 4. Требования к устройству

- Платформа: Android 8.0 (API 26) и выше.
- `targetSdkVersion`: 34 (Android 14).
- Устройства: смартфоны и планшеты, портретная ориентация.
- Интернет: не требуется, приложение полностью офлайн.
- Специальное оборудование: не требуется. Вибрация, уведомления и камера —
  опциональны, без них приложение работает.
- Размер APK: около 25,9 МБ (универсальный APK, `arm64-v8a` + `armeabi-v7a`).
- ABI: `arm64-v8a` и `armeabi-v7a`; x86/x86_64 в release не входят и нужны
  только эмулятору в debug.
- Разрешение экрана: любое; интерфейс адаптивный, скриншоты сняты на
  1080×2400.

Если поле свободное, можно вставить:

> Android 8.0 и выше (minSdk 26, targetSdk 34). Смартфоны и планшеты.
> Интернет не требуется. Специальное оборудование не нужно; вибрация,
> уведомления и камера опциональны.
