# Публикация «ГириБро» в RuStore

Практический чек-лист для первой публикации. Официальная документация:

- [Как опубликовать приложение](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication)
- [Правила модерации RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps)
- [Как настроить подписание приложения](https://www.rustore.ru/help/guides/sign-apk)

## 1. Что уже готово в проекте

- Release-сборка подписывается ключом из `keystore.properties` (файл и каталог
  `keystore/` не попадают в Git).
- Пакет: `ru.petproject.giribro`, `minSdk 26`, `targetSdk 34`.
- Приложение не использует интернет, аккаунты, аналитику и рекламу.
- Все тренировки, замеры, настройки и фото-карточки остаются на устройстве.
- Есть тёмная и светлая темы, русский интерфейс, фото-карточки с экспортом и
  системным «Поделиться».
- Подготовлены иконка 512×512 и скриншоты 1080×1920 в `docs/rustore/`.
- В настройках есть «О приложении» и встроенная политика конфиденциальности.

## 2. Что нужно получить/подготовить перед загрузкой

- [ ] Аккаунт разработчика в [RuStore Консоль](https://console.rustore.ru/sign-in).
- [ ] Публичное имя разработчика (ФИО/ИП/название компании).
- [ ] E-mail поддержки — обязателен хотя бы один способ связи.
- [ ] Публичный URL политики конфиденциальности на русском языке.
- [ ] Та же политика доступна внутри приложения.
- [ ] Иконка 512×512 px, PNG/JPG, до 3 МБ, без прозрачности по краям.
- [ ] Не менее 3 скриншотов для телефона, PNG/JPG, до 3 МБ каждый,
      рекомендуемое соотношение сторон 16:9.
- [ ] Краткое описание до 80 символов.
- [ ] Полное описание до 4000 символов.
- [ ] Категория, возрастной рейтинг, до 5 поисковых тегов.
- [ ] Текст «Что нового?».
- [ ] Заполненная декларация разрешений и безопасности данных.

## 3. Подпись release-сборки

Подпись настраивается через `keystore.properties` в корне проекта:

```properties
storeFile=keystore/giribro-release.jks
storePassword=...
keyAlias=giribro
keyPassword=...
```

Шаблон лежит в `keystore.properties.example`. Реальный `keystore.properties`,
каталог `keystore/`, файлы `*.jks` и `*.keystore` добавлены в `.gitignore`.

Сборка:

```powershell
.\gradlew.bat assembleRelease --no-parallel
```

Подписанный APK: `app\build\outputs\apk\release\app-release.apk`.

Проверка подписи:

```powershell
apksigner verify --verbose --print-certs app\build\outputs\apk\release\app-release.apk
```

Важно: ключ подписи нельзя терять. Без него не получится выпустить обновление
с той же подписью. Сохраните `keystore/giribro-release.jks` и пароли из
`keystore.properties` в надёжном месте (например, в менеджере секретов и на
отдельном носителе).

## 4. Политика конфиденциальности

Приложению нужна политика на русском языке, доступная по публичной ссылке и
внутри приложения. Черновик: [privacy-policy.md](privacy-policy.md).

Внутри приложения политика открывается в «Настройки» → «Документы» →
«Политика конфиденциальности». Контакты и ссылка для этого экрана задаются в
`app/src/main/res/values/legal.xml`.

Перед публикацией замените:

- `[ИМЯ РАЗРАБОТЧИКА]` — ФИО/ИП/название;
- `[EMAIL]` — контакт поддержки;
- `[URL ПОЛИТИКИ]` — публичная ссылка;
- `[ДАТА]` — дата вступления в силу.

Те же значения должны попасть в `app/src/main/res/values/legal.xml`,
[privacy-policy.md](privacy-policy.md) и [rustore-listing.md](rustore-listing.md).
Пока в этих файлах остаются значения в квадратных скобках, APK нельзя
отправлять на модерацию.

Публичную ссылку можно получить, например, через GitHub Pages, сайт проекта
или другой статический хостинг. Ссылка должна открываться без авторизации.

Для публикации подготовлен готовый HTML:
[privacy-policy.html](privacy-policy.html). В нём остаются только
`[ИМЯ РАЗРАБОТЧИКА]` и `[EMAIL]` — замените их перед выкладкой.

Самые простые варианты:

1. **GitHub Pages.** Загрузите файл `docs/privacy-policy.html` в репозиторий,
   включите Pages для каталога `/docs`, откройте
   `https://<аккаунт>.github.io/<репозиторий>/privacy-policy.html`.
2. **Netlify Drop / Cloudflare Pages.** Перетащите папку с одним
   `privacy-policy.html` в сервис и получите постоянный URL.
3. **Telegraph.** Опубликуйте текст политики как страницу и используйте
   `https://telegra.ph/...`; это быстро, но менее «официально», чем свой сайт.

Не используйте ссылку на скачивание файла или архив: модерация ожидает
открывающуюся веб-страницу.

## 5. Иконка и скриншоты

Требования RuStore:

- иконка: 512×512 px, PNG/JPG, до 3 МБ, фон заполнен по всей площади;
- скриншоты: не менее 3 для телефона, PNG/JPG, до 3 МБ, максимум 2160×3840;
- рекомендуемое соотношение сторон — 16:9;
- если картинка больше 16:9, RuStore обрежет её до 16:9.

В проекте есть исходные скриншоты 1080×2400. Для карточки лучше подготовить
отдельные PNG 1080×1920 (16:9), чтобы не потерять верх и низ интерфейса.
Файлы для загрузки складывайте в `docs/rustore/` (этот каталог можно
коммитить).

Готовые медиафайлы:

- `docs/rustore/icon-512.png` — иконка 512×512;
- `docs/rustore/screenshots/01-diary.png` — дневник;
- `docs/rustore/screenshots/02-workout-card.png` — фото-карточка;
- `docs/rustore/screenshots/03-stats.png` — статистика;
- `docs/rustore/screenshots/04-norms.png` — нормативы;
- `docs/rustore/screenshots/05-calendar.png` — календарь ВФГС;
- `docs/rustore/screenshots/06-timer.png` — настройка таймера;
- `docs/rustore/screenshots/06-timer-running.png` — работающий таймер.

Для карточки RuStore достаточно 3–6 скриншотов. Рекомендуемый порядок:
дневник, фото-карточка, статистика, нормативы, календарь, таймер.

## 6. Черновик карточки

Готовый текст для копирования: [rustore-listing.md](rustore-listing.md).

Перед отправкой на модерацию проверьте:

- [ ] название не длиннее 30 символов;
- [ ] краткое описание не длиннее 80 символов;
- [ ] полное описание не длиннее 4000 символов;
- [ ] нет обещаний лечения, медицинских гарантий и чужих товарных знаков;
- [ ] скриншоты соответствуют текущей версии приложения;
- [ ] в описании нет ссылок на конкурирующие магазины приложений.

## 7. Загрузка в RuStore Консоль

1. Войдите в RuStore Консоль под аккаунтом с ролью «Владелец компании».
2. Создайте приложение и укажите название.
3. Загрузите подписанный APK (`app-release.apk`).
4. Дождитесь обработки файла. Обработанные файлы хранятся 14 дней.
5. Заполните карточку: описание, категория, возрастной рейтинг, контакты,
   иконка, скриншоты, «Что нового?».
6. Заполните декларацию разрешений и безопасности данных.
7. Отправьте версию на модерацию.
8. После одобрения выберите способ публикации (сразу или отложенно).

## 8. Разрешения приложения

В манифесте используются:

- `VIBRATE` — вибрация таймера;
- `POST_NOTIFICATIONS` — уведомление о работе таймера;
- `FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_SPECIAL_USE` — foreground-сервис
  таймера, чтобы отсчёт продолжался при свёрнутом приложении.

Нет `INTERNET`, доступа к контактам, геолокации, камере и внешнему хранилищу.
Фото-карточка сохраняется через системный файловый диалог, а отправляется через
системное «Поделиться» — приложение не получает доступ к чужой галерее.

## 9. После публикации

- Следите за отзывами в RuStore Консоли.
- Для обновления увеличивайте `versionCode`, не меняйте `applicationId` и
  подписывайте тем же ключом.
- Храните исходники и ключ отдельно друг от друга.
- При изменении политики обновляйте дату и публичный URL.
