## 1. Что уже готово в проекте

- Release-сборка подписывается ключом из `keystore.properties` (файл и каталог
  `keystore/` не попадают в Git).

- Приложение не использует интернет, аккаунты, аналитику и рекламу.

  устройстве.

  системным «Поделиться», черновик тренировки, профиль для нормативов, ярлыки
  быстрого запуска.

  автобэкап в выбранную папку и напоминание, если копии нет дольше 30 дней.
- Подготовлены иконка 512×512 и скриншоты 1080×1920 в `docs/rustore/`.
- В настройках есть «О приложении» и встроенная политика конфиденциальности.

## 3. Подпись release-сборки

Подпись настраивается через `keystore.properties` в корне проекта:

```properties
storeFile=keystore/giribro-release.jks
storePassword=...
keyAlias=giribro
keyPassword=...
```

Шаблон лежит в `keystore.properties.example`. Реальный `keystore.properties`,
каталог `keystore/`, файлы `*.jks` и `*.keystore` добавлены в `.gitignore`.

Сборка:

```powershell
.\gradlew.bat assembleRelease --no-parallel
```

Подписанный APK: `app\build\outputs\apk\release\app-release.apk`.

Проверка подписи:

```powershell
apksigner verify --verbose --print-certs app\build\outputs\apk\release\app-release.apk
```

Важно: ключ подписи нельзя терять. Без него не получится выпустить обновление
с той же подписью. Сохраните `keystore/giribro-release.jks` и пароли из
`keystore.properties` в надёжном месте (например, в менеджере секретов и на
отдельном носителе).

## 5. Иконка и скриншоты

Требования RuStore:

- иконка: 512×512 px, PNG/JPG, до 3 МБ, фон заполнен по всей площади;
- скриншоты: не менее 3 для телефона, PNG/JPG, до 3 МБ, максимум 2160×3840;
- рекомендуемое соотношение сторон — 16:9;
- если картинка больше 16:9, RuStore обрежет её до 16:9.

В проекте есть исходные скриншоты 1080×2400. Для карточки лучше подготовить
отдельные PNG 1080×1920 (16:9), чтобы не потерять верх и низ интерфейса.
Файлы для загрузки складывайте в `docs/rustore/` (этот каталог можно
коммитить).

- `docs/rustore/screenshots/03-stats.png` — статистика;

## 7. Загрузка в RuStore Консоль

1. Войдите в RuStore Консоль под аккаунтом с ролью «Владелец компании».
2. Создайте приложение и укажите название.
3. Загрузите подписанный APK (`app-release.apk`).
4. Дождитесь обработки файла. Обработанные файлы хранятся 14 дней.
5. Заполните карточку: описание, категория, возрастной рейтинг, контакты,
   иконка, скриншоты, «Что нового?».
6. Заполните декларацию разрешений и безопасности данных.
7. Отправьте версию на модерацию.
8. После одобрения выберите способ публикации (сразу или отложенно).

## 8. Разрешения приложения

В манифесте используются:

- `CAMERA` — фронтальная камера для счётчика повторов; видео по выбору
  пользователя сохраняется в выбранную им папку через SAF;
- `VIBRATE` — вибрация таймера;
- `POST_NOTIFICATIONS` — уведомление о работе таймера и напоминание о копии;
- `FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_SPECIAL_USE` — foreground-сервис
  таймера, чтобы отсчёт продолжался при свёрнутом приложении;
- `WAKE_LOCK` — WorkManager завершает фоновую автокопию при заблокированном
  экране;
- `RECEIVE_BOOT_COMPLETED` — восстанавливает расписание автобэкапа после
  перезагрузки телефона.

Нет `INTERNET`, `ACCESS_NETWORK_STATE`, доступа к контактам, геолокации,
микрофону и ко всей файловой системе. `CAMERA` используется только для
необязательного счётчика повторов: кадры обрабатываются на устройстве, а видео
в режиме «Запись» сохраняется через SAF в выбранную пользователем папку.
Фото-карточка сохраняется через системный файловый диалог, а отправляется через
системное «Поделиться» — приложение не получает доступ к чужой галерее. Для
автобэкапа и видео используется SAF: доступ выдаётся только к папке, которую
пользователь выбрал сам.

Готовые ответы для полей «Запрашиваемые данные», «Чувствительные разрешения»,
«Интеграции» и «Требования к устройству» — в [rustore-form.md](rustore-form.md).

Коротко: данные не собираются и не передаются (нет даже `INTERNET`),
интеграций и сторонних SDK нет, требуемая версия Android — 8.0 (API 26) и выше.

## 9. После публикации

- Следите за отзывами в RuStore Консоли.
- Для обновления увеличивайте `versionCode`, не меняйте `applicationId` и
  подписывайте тем же ключом.
- Храните исходники и ключ отдельно друг от друга.
- При изменении политики обновляйте дату и публичный URL.
